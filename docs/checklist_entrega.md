# Lista de verificación de entrega

## Código y evidencia

- [ ] Personalizar el proyecto si deseas añadir datos o identidad visual propia.
- [ ] Ejecutar los 15 escenarios con `pytest` y confirmar `15 passed`.
- [ ] Revisar `reports/reporte.html` y las 15 capturas de `reports/screenshots/`.
- [ ] Incluir el reporte y las capturas en el repositorio antes del commit final (si permanecen ignorados, usar `git add -f reports/reporte.html reports/screenshots/*.png`).
- [ ] Confirmar que no se incluyan `.venv`, `.deps`, `instance/` ni secretos.

## Servicios externos obligatorios

- [ ] Crear cinco historias separadas en Jira o Azure DevOps usando `docs/historias_usuario.md`.
- [ ] Añadir criterios de aceptación y rechazo dentro de cada historia.
- [ ] Verificar que el tablero sea público o que el profesor/monitor tenga acceso.
- [ ] Crear un repositorio GitHub público y subir el código, reporte y capturas.
- [ ] Grabar la ejecución real siguiendo `docs/guion_video.md`.
- [ ] Subir el video a YouTube o OneDrive; no usar Google Drive.
- [ ] Abrir los tres enlaces desde una ventana privada para validar permisos.
